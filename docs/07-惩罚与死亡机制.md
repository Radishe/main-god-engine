## 0. 审计发现（2026 全量审计）

> 本节是本轮审计在**本章**发现的问题。**§0.1 是全项目最严重的缺口。**

### 0.1 ★★★ 「副本内死亡」的常规流程从未定义

**严重度：最高** ｜ **位于游戏最核心的循环上**

**本章及全库现有的全部死亡相关表述**：

| 出处 | 内容 |
| :--- | :--- |
| [01](01-核心设计哲学.md) §4.1 | 副本内部的……甚至**角色死亡**……都是副本沙盒内的**局部状态**，不直接写入主神账本 |
| 本章 §5 | 一阶~二阶永不触发永久死亡，**死亡降级为「严重失败 + 高额扣点」**；三阶以上需 `lethal: true` |
| [06](06-物品与公证体系.md) §2 | `droppable` 物品「死亡或严重失败时**概率掉落**」 |
| [01](01-核心设计哲学.md) §11 | 剧本字段有「失败结算（永久死亡？扣除？**强制退出**？）」——**只是待填字段名** |

**核心断裂（三点）**：

1. **"副本内死亡"到底意味着什么？**
   - 01 章说它是"沙盒内的局部状态" → 暗示死亡不真实，玩家会复活/退出
   - 本章说死亡可"降级为严重失败" → 暗示死亡是失败的一种
   - **两处描述的是不同的事**，且从未对账

2. **死亡与抹杀是两套系统，从未区分**
   - **副本内死亡** = 角色在副本里被打死（可能是常态，甚至被设计成必然）
   - **抹杀** = 主神对玩家的终极惩罚（D1 的"三次失败"）
   - **二者关系完全未定义**：副本内死亡算不算一次失败？**算不算进"三次"计数？**

3. **非 lethal 副本里玩家死了，接下来发生什么？**（**本章无任何说明**）

| 若采用 | 后果 |
| :--- | :--- |
| 复活继续打 | "死亡"没有代价，`droppable` 的概率掉落成为唯一后果 |
| 直接退出副本 | 结算按什么评价？未完成任务 → 低分，但没死 |
| 计为一次严重失败 | 应触发 D1 的 A→B→C 抵扣与计数，但文档没说 |

**由此产生的两个漏洞**：

- 若"死亡 = 退出副本" → **玩家可主动送死，快速逃离高难度任务**
- 若"死亡 = 复活" → **死亡毫无威慑**，本章 §5 的永久死亡保护变得多余

> **这是必须先解决的前置问题**：它决定本章整个惩罚体系如何与副本循环对接。
> **在定下这一点之前，本章 §2/§3/§5 的惩罚规则都无法最终定稿。**

### 0.2 本章内部的自相矛盾（两处，其中 (a) 已修复）

| 出处 | 问题 |
| :--- | :--- |

### 0.3 两套惩罚体系未映射

| 体系 | 出处 | 内容 |
| :--- | :--- | :--- |
| **D/E/F 失败三档** | 本章 §2 | 完成度系数 0.3 / 0 / 负数，对应扣押金与扣点 |
| **A/B/C 抵扣顺序** | D1 | 惩罚额 = f(任务体量)，依次扣 兑换点 → 属性点 → 物品 |

**二者并行存在，但从未说明如何映射**：
- D/E/F 是**惩罚档位**，A/B/C 是**抵扣来源**——是"先定档位再抵扣"，还是两套独立？
- D1 的 A→B→C 需要把**属性点**与**物品**折算成同一种标量（才能判断"A 不足"），
  但**属性点 → 兑换点 无汇率**，**物品无估值规则** → **B、C 两档在数值上无法执行**

> 另见 [05](05-玩家成长体系.md) §1.3（属性扣减的连锁问题）与 [06](06-物品与公证体系.md) §2（`permanent` 与惩罚冲突）。

## 3. 严重失败递增机制

> ⚠️ **与 D1 冲突，待用户裁决**：本节为「按阶位重置 3/2/1」，D1 为「累计三次抹杀」，两者未对账；[09 章细节 2](09-待确认细节.md) 亦倾向前者。见 [技术债 T2](技术债与盲点.md#t2)。本轮不替用户选择口径。

严重失败与副本内隐藏评分挂钩，**递增式**：

- 每次严重失败，计一次严重失败计数。
- **计数按阶位重置**：每晋升一阶，计数清零。
- **高阶容错更低**：一阶允许 3 次，二阶允许 2 次，三阶以上允许 1 次。
- 达到阈值 → **抹杀**。

**设计意图**：把「永久死亡」从「随机概率」变成「累积后果」。玩家每次严重失败都在逼近死亡线，而不是每次进副本都掷骰子。这更可控，也更有叙事张力。

> 该项对应 [09-待确认细节.md](09-待确认细节.md) 细节 2（倾向选项 B）。

### 3.1 触发严重失败计数的条件清单

- 结算评价为 F。
- 副本内主动放弃。
- 触发致命违规（如利用副本机制漏洞刷取收益，经主神判定）。
- 晋升试炼失败。

## 4. 抹杀规则

**抹杀 = 进度清空 + 保留纪念标记**，不是删档。

- 角色回到初始状态（一阶、属性归零、物品清空、技能清空）。
- 玩家保留一个「曾到达 X 阶」的纪念标记（类似死亡记录）。
- 抹杀有痛感，但不至于让玩家彻底弃游。

**单存档约束**：游戏只有一个存档，玩家就是一个「真实的人」。抹杀不可回滚。这强化了无限流的严肃性。

## 5. 永久死亡保护

> ⚠️ **表头歧义（审计 F14）**：表头只有一个「阶位」，但两行需分别读作玩家阶位与副本阶位，「一阶玩家进入三阶副本是否受保护」两行给出相反答案。详见 [05](05-玩家成长体系.md) §0.4 与 §3.2 的就地标注。本轮仅标注，不改表。

| 玩家阶位 | 永久死亡保护 |
| :--- | :--- |
| 一阶 ~ 二阶 | 永不触发永久死亡。即使进入高阶副本，死亡降级为「严重失败 + 高额扣点」 |
| 三阶以上 | 可能触发永久死亡，且需副本声明 `lethal: true` |

**`lethal` 声明权**：建议高阶副本默认允许 `lethal`，作者可以选择关闭（但关闭后收益打折），防止作者为了收益滥用永久死亡。

## 6. 逾期未进入副本

> ⚠️ **本节有两项依赖悬空，且押金主语已失效**：①「下一个应进副本」的分配规则全库不存在，押金基数无法计算；②「休息期」时长规则不存在，「休息期延长令」无法作用于未定义的时间段。且 D1 已推翻押金公式，「押金基数 / 扣押金全额」两句的引用对象已失效。详见 §0.2(b)。本轮仅标注，不补写规则。

- 判定为**中等失败**（E 档）。
- 押金基数取「下一个应进副本」的押金上限。
- 扣押金全额，扣当前兑换点 10%。
- 完成度系数 0，不产出任何收益。
- 计入阶位进度负向标记。
- 连续逾期两次触发惩罚副本（难度等于当前阶位，收益打八折）。
- 仅可用休息期延长令豁免。

## 7. 失败惩罚的执行者

**惩罚的执行者永远是主神引擎，不是副本脚本。**

副本只能申报「失败」这个事件，后果由主神裁定。副本不能自己写「失败者直接删号」，它只能触发「失败」这个事件。

## 8. 最终兑换点公式

> ⚠️ **顺序已由 [D12](设计决议记录.md) 修正**：正确链条为「先算分值 → 达成率 → 定级 → 取该级系数」，而非把「完成度系数」当作公式输入查表得到。下方公式与系数表保留原文以维持溯源，**本轮未改动公式或任何系数数值**；「基础产出值」无表定义且与阶位区间量纲耦合（审计 F5/G2），待用户拍板。

> 最终兑换点 = 基础产出值 × 阶位系数 × 完成度系数 × 效率系数 × 惩罚系数

- 基础产出值：来自主神侧任务/物品/能力值表。
- 阶位系数：新手 0.5 到十阶 512.0（占位，待拟合）。
- 完成度系数：S=2.0 到 F=负数。
- 效率系数：1.0 + min(上限, 内部资源余额 / 目标基准总值 × 系数)。加成上限由玩家阶位决定。
- 惩罚系数：失败侧按精神和失败表修正，下限 0.5。

| 完成度系数 | [03-评分与评价体系.md](03-评分与评价体系.md) | S=2.0 / A=1.3 / B=1.0 / C=0.7 / D=0.3 / E=0 / F=负数 |
