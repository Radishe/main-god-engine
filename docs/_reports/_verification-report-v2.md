## 二、发现的问题

### 问题 1（数字口径不准确，建议修正）· README:123「API 单次返回上限约 100KB」

**原文**（`docs/README.md:123`）：

> 分享链接的 API 单次返回上限约 100KB，且被 Deep Search 的搜索结果元数据占满，导致**助手第 3 轮起的回答无法通过接口取得**。

**实测数据**：

| 对象 | 字节数 | KiB | 字符数 |
| :--- | :--- | :--- | :--- |
| `_share_raw.txt`（API 抓取结果） | 127570 | **124.6 KiB** | 100255 |
| `DeepSeek - 探索未至之境.html`（HTML 导出） | 524948 | 512.6 KiB | — |

**问题**：`100255` 是**字符数**（UTF-16 code units），不是字节数；文件字节数是 127570（约 125KB）。因此「约 100KB」按字节计不成立。

**责任归属（如实说明）**：这个错误**源自我 v1 报告**——我当时用 `$t.Length` 得到 100255 并误当作字节数写入 v1 报告（v1 未逐字核对字节/字符口径），lead 据此写入 README。**是我先引入的口径错误，不是 lead 的编造，也不影响任何实质结论。**

**建议**：改为「API 单次返回的正文量有限（约 100K 字符 / 125KB 字节），且被 Deep Search 的搜索结果元数据占满」，或直接写「API 单次返回量不足以取回全部 16 轮」。**另需说明**：「API 单次返回上限约 100KB」这一**上限值本身在素材中无出处**（我们只知道本次返回了这些量），严格说属推断，建议加「推测」或改为对本次事实的陈述。

**附带订正**：v1 报告中「_share_raw.txt 共 100255 字节」的表述同样是字符/字节口径错误，**以本报告为准**（真实字节数 127570）。v1 的实质结论（第 3 轮 RESPONSE 缺失）不受影响，本轮已重新确认。
