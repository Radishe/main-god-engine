## 二、本轮新发现的矛盾（技术债未记录）

### A1 · `permanent` 物品与惩罚扣除直接冲突 ★★

**严重度：高** ｜ **后果：惩罚规则无法执行**

| 出处 | 内容 |
| :--- | :--- |
| `06-物品与公证体系.md` §2 | `permanent` = **永久绑定，不可交易、不可丢弃** |
| `设计决议记录.md` D1 | 惩罚抵扣顺序 A(兑换点)→B(属性点)→**C(物品)** |

**矛盾**：惩罚要扣物品，但 `permanent` 物品被定义为**不可丢弃**。

**由此产生三个必须回答的问题**：

1. `permanent` 物品**能否**被惩罚扣除？
   - 若能 → 那"不可丢弃"是假的，定义要改
   - 若不能 → 那这类物品**天然免疫惩罚**，玩家会把资产尽量转成 `permanent` 来躲避惩罚（**与 D1 的立法意图直接冲突**）
2. `droppable` 定义为"死亡或严重失败时**概率**掉落"——这与 D1 的"**确定**抵扣"是两套机制，**谁优先**？
3. 惩罚扣物品时，是玩家**自选**（可交出垃圾物品），还是主神**按价值抽取**？
   - 自选 → 惩罚可被轻易规避
   - 抽取 → 需要"物品价值排序"机制，**文档未定义**

> **这正是 D1 落地前必须解决的前置问题。**

### A2 · 「观察者模式」与「主线优先」语义冲突 ★

**严重度：中** ｜ **后果：观察者副本的结算规则无法确定**

| 出处 | 内容 |
| :--- | :--- |
| `设计决议记录.md` D2 | 观察者**不触发主线任务以外的任何任务** |
| `设计决议记录.md` D8 | 主线成功 → 支线按 100% 计；主线失败 → 支线按 50% 计 |

**矛盾**：D2 的表述**暗示观察者可以触发主线任务**，但"观察者"一词的语义是**旁观**。

**两种理解都导致问题**：

- 若观察者**能**做主线 → 它就不是观察者，D2 的"视角限制"形同虚设
- 若观察者**不能**做主线，只是"不触发支线" → 那它在副本里做什么？D8 的主线优先规则对它**完全无意义**

**需要明确**：观察者进入副本的**目的**是什么？（旁观剧情？评估副本？保护某人？）目的决定它能做什么。

### A3 · 属性点被扣后与阶位要求的关系断裂 ★

### A7 · 「副本内死亡」的常规处理流程从未定义 ★★★

**严重度：最高** ｜ **后果：核心玩法链条断裂**

这是本次审计发现的**最严重问题**，因为它位于游戏最核心的循环上。

**文档现有的所有死亡相关表述**：

| 出处 | 内容 |
| :--- | :--- |
| `01:105` | 副本内部的……甚至**角色死亡**……都是副本沙盒内的**局部状态**，不直接写入主神账本 |
| `07:80-81` | 一阶~二阶永不触发永久死亡，**死亡降级为「严重失败 + 高额扣点」**；三阶以上需 `lethal: true` |
| `06:66` | `droppable` 物品「死亡或严重失败时**概率掉落**」 |
| `01:511` | 剧本字段草案里有「失败结算（永久死亡？扣除？**强制退出**？）」——**但这只是待填的字段名，不是机制** |

**核心断裂**：

1. **"副本内死亡"到底意味着什么？**
   - 01 章说它是"沙盒内的局部状态" → 暗示**死亡不真实**，玩家会复活/退出
   - 07 章说死亡可"降级为严重失败 + 高额扣点" → 暗示**死亡是失败的一种**
   - **两处描述的是不同的事**：一个是"副本内角色状态"，一个是"结算后果"

2. **死亡与抹杀是两套系统，但从未区分**
   - **副本内死亡** = 角色在副本里被打死（可能是常态，甚至设计成必然）
   - **抹杀** = 主神对玩家的终极惩罚（D1 的"三次失败"）
   - **二者的关系完全未定义**：副本内死亡算不算一次"失败"？算不算进"三次"计数？

3. **非 lethal 副本里玩家死了，接下来发生什么？**
   - 复活继续打？ → 那"死亡"没有代价，`droppable` 的"概率掉落"是唯一后果
   - 直接退出副本？ → 那结算按什么评价？（未完成任务 → 低分 → 但没死）
   - **文档没有任何一处说明这个流程**

4. **由此产生的连锁问题**：
   - 若"死亡 = 退出副本"，则**玩家可以主动送死来快速退出**（逃避高难度任务的捷径）
   - 若"死亡 = 复活继续"，则**死亡毫无威慑**，07 章的永久死亡保护变得多余
   - 若"死亡 = 严重失败"，则**它应触发 D1 的抵扣与计数**，但文档没说

> **这是必须先解决的前置问题**：它决定 07 章整个惩罚体系如何与副本循环对接。

### F1 的 Lead 独立验算（关键证据）

**子代理的论证**：`512000 / 512 = 1000` 恰好等于一阶下限，说明 512000 才是与阶位系数同一套翻倍体系的值；而 `768000 / 512 = 1500`，不闭合。

**Lead 复核结果**：**成立。**

| 检验 | 结果 |
| :--- | :--- |
| 1000 × 2⁹（9 次翻倍） | = **512000** ✓ |
| 512000 ÷ 512（十阶系数） | = **1000** = 一阶下限 ✓ **完美闭合** |
| 768000 ÷ 512 | = 1500 ✗ |
| 768000 是否 2 的整数次幂×1000 | 768 = 3×2⁸ → **×2^9.585**，非整数次幂 ✗ |
| 768000 是否 ×3 曲线 | 1000×3⁶ = 729000，接近但 ≠ 768000 ✗ |

**结论**：**768000 是孤立异类，应改为 512000。** 且文档自带的「一阶 1000~2999 / 二阶 3000~5999」两个样本本身也不满足无歧义翻倍（2000→3000 不是等比）。

### F9 的 Lead 验算（收益增长失衡）

| 阶位 | 体量下限 | 阶位系数 | B 级收益 |
| :--- | ---: | ---: | ---: |
| 一阶 | 1000 | 1.0 | 1000 |
| 二阶 | 2000 | 2.0 | 4000 |
| 三阶 | 4000 | 4.0 | 16000 |
| 四阶 | 8000 | 8.0 | 64000 |

**收益每阶 ×4，而体量每阶 ×2** → 玩家永远倾向升阶冒险，D5 的「低风险低收入」被收益曲线压过。
**更尖锐的推论**：完美通关低阶副本，可能仍不如低完成度通关高一阶副本。

## 三、数值自洽性验算（本轮新发现）❌

**这是文档自述缺口之外的问题**：09 章表格标注了"待拟合"，但**表格内部彼此矛盾**，不是"还没调好"，而是"调不到一起"。

### N1 · 阶位区间：`每阶翻倍` 与 `十阶下限 768000` 不符

**已知**：一阶下界 1000、二阶区间 3000~5999、十阶下限 768000、增长方式"每阶翻倍"

**验算一（区间宽度翻倍）**：

| 阶 | 区间 |
| :--- | :--- |
| 1 | 1000 ~ 2999 |
| 2 | 3000 ~ 6999 |
| … | … |
| 10 | **1023000** ~ 2046999 |

→ 十阶**下界**推得 **1023000**，文档写 **768000**（**差 1.33 倍**）

> ⚠️ **勘误**：本报告初稿此处曾误写"下限推得 2047000（差 2.67 倍）"——2046999 是**上界**，1023000 才是下界。已订正，**核心结论不变**。详见 [审计裁定与勘误.md](审计裁定与勘误.md)。

**验算二（下界每阶翻倍）**：

| 阶 | 下界 |
| :--- | --- |
| 1 | 1000 |
| 2 | 2000 |
| … | … |
| 10 | 512000 |

→ 推得 **512000**，与 768000 不符

**验算三（用 768000 反解等比）**：r ≈ 2.0922，则二阶下界应为 **2092**，文档写 **3000**

**结论**：三项数据**无法同时成立**。且"二阶区间 3000~5999"本身的宽度（3000）不是一阶宽度（2000）的整数倍，**"每阶翻倍"的表述与实际数据矛盾**。

> **`768000` 是异类的最强证据**：`512000 ÷ 512（十阶系数）= 1000 = 一阶下限`（完美闭合）；
> 而 `768000 ÷ 512 = 1500`（不闭合）。

### N2 · 阶位系数：`每阶翻倍` 与 `十阶 512.0` 差一阶

| 阶 | 系数（每阶翻倍） |
| :--- | :--- |
| 1 | 1.0 |
| 2 | 2.0 |
| … | … |
| 10 | **1024.0** |

→ 文档写 **512.0**。

**若"十阶 512"正确**，则应为**每阶翻倍但从新手起算**（新手 0.5 → 一阶 1.0 → 十阶 512.0 需要 10 次翻倍，正好 `0.5×2^10 = 512`）——**即：从"新手"到"十阶"是 10 次翻倍，而非 9 次**。这说明"阶"的计数方式需明确（新手算不算第 0 阶）。

### N3 · 增长模型跨表不统一

| 表 | 首值 → 末值 | 倍数 | 模型 |
| :--- | :--- | :--- | :--- |

## 七、给用户的结论

1. **框架思想是完整且自洽的**，问题**全部集中在"从原则到可执行规则"的最后一公里**。
2. **技术债记录本身是准确的**，但**漏了 8 项更基础的问题**（A1~A8）与**3 项数值矛盾**（N1~N3）。
3. **最严重的不是任何一条既有技术债，而是 A7**：
   **「副本内死亡」的常规流程从未被定义**——它位于游戏最核心的循环上，
   且决定了 07 章整个惩罚体系如何落地。
4. **好消息**：两大盲区 T4/T8 **在现有框架内已有解法**，不需要新创意——
   **只是没人把它们和已有内容连起来**。
   - ⚠️ **但 T4 的解法依赖 N1 先修好**（表内部矛盾则无法作为标准）。
5. **真正的无解项只有 T3**（"收益风险是否成正比"的量化）。
6. **建议下一步**：
   - **先定 A7**（副本内死亡 → 决定惩罚体系走向）
   - **再修 N1 + A1 + A3**（三项阻塞，一修则 T4/T1/T2 自动松动）
   - 最后清 A5/A6/T2/T5 等"定义缺失"类（成本低、收益快）
