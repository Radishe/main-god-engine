## 3. 分歧裁决

- **产品胜规格之争**：`HANDOFF: READY` 达成，规格齐备，不该再补设定。
- **工程胜风险之争，败在处方**：缺口真实，但多数可边派边补，不构成开工阻断。关键约束——缺失的 own 测试文件在受保护区、agent 补不了，**不能把这些算成 agent 的验收责任**，由 maintainer 并行补。
- **红队败在结论、胜在事实**：一票否决驳回（单机+可信 agent 场景，理论伪造≠实践发生）；但其 git/远端发现转化为一个必须立即做的动作（commit），不是停工令。

**关于 recipe 逐字匹配的定性**：裁决为「当前按脆弱性处理，不是防篡改特性」。它防的是善意重构而非攻击者（真攻击者能写 gates/ 就直接改 baseline，hash 不覆盖）；但它只是「CI 变红提醒维护者更新配方」，不是数据损坏——所以是**并行摩擦**，不是**安全闸门**。

## 4. 最终裁决：**派。唯一硬条件是 commit。**

> **现在 `git add -A && git commit` 让裁判面进入可回滚历史（1 分钟）→ 立刻派活。**
> 远端 / branch protection / CI 上线是「合入条件」，不是「开工条件」——等它才开工才会停摆。

### A. 本机现在做（commit 前后，都不阻断派活）

1. **`git add -A && git commit`** — 唯一硬条件，让 gates/tests、baseline、CODEOWNERS 进历史可回滚。
2. `common.py` 的 `EXIT` 加 `"DEFERRED": 3` — 消除 x05-01 潜在 KeyError（2 行）。
3. maintainer 补 P2/P6/P7 缺失的 4 个 own 测试文件（在 gates/tests/，不派给实现 agent）。
4. 修订 P1/P5 工单里「I6 仍绿」为「I6 PENDING 直至 P5 落地」，与 CI 对齐。

### B. 必须发起人做的外部动作（agent 交付后、合入前完成即可）

1. `git remote add origin <地址>` + `git push`。
2. GitHub 端开 branch protection：`@Radishe` review + `gate-approved` 标签仅 owner 可打。
3. 确认 Actions 启用。

### C. 推荐派活批次（来自工程维度，裁决采纳）

| 批次 | 包 | 说明 |

- 分片只读快照 + 精确 writable 边界；显式声明 `gates/`/`config/`/`.github/`/`tests/pN/` 不可写。
