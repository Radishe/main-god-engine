# 远端同步说明（2026-11-27）

> 一份操作记录，解释为什么本地 `git status` 可能显示 `ahead 1`，以及如何一键消解。

## 发生了什么

推送三条 MISSING 细化用例时，git HTTPS 通道反复报 `schannel: server closed abruptly` / `CONNECT tunnel failed 502`。API 通道（走同一代理的 `api.github.com`）正常。

为完成推送，改用 GitHub API 逐文件同步：创建 blob → 构造 tree → 创建 commit → 更新 `refs/heads/main`。结果：

- **远端 main** = `423d0e3e6376d0e7b0e38c07c91040d32ca978d2`，含三条新测试、baseline PASS=44、完整 commit message
- **本地 HEAD** = `1ec6b70`（同样内容，但 git commit 对象由本地生成，hash 与 API 创建的远端 commit 不同）
- 本地 `origin/main` tracking ref 仍停在旧 hash → `git status` 显示 `ahead 1`

## 为什么内容没问题

API 同步时逐文件写入了 6 个变更文件（3 个测试 + baseline + 2 个 evidence），远端 commit message 与本地一致，三条测试文件经 API 查均 HTTP 200。CI 在远端独立跑，读的是远端内容——正确。

hash 不同只是「同一个内容有两次独立的 commit 对象」，不影响功能。

## 如何消解 ahead 1/2（网络恢复后，一键）

```bash
cd D:/VirtualSharing/VirtualSharing/dsh/games
git fetch origin
git reset --hard origin/main
```

`fetch` 会把远端 commit 对象 `423d0e3` 拉到本地，`reset` 将本地 HEAD 指过去。两边内容相同，`reset` 不会丢失任何工作。

## 验证方式

```bash
git status -sb                      # 应显示 ## main...origin/main（无 ahead）
python gates/check.py --run         # PASS=44 FAIL=5 PENDING=12 MISSING=11
```

远端状态也可用 API 查（无需 token 的读操作）：

```bash
curl -s https://api.github.com/repos/Radishe/main-god-engine/commits/main | grep '"sha"'
```
