## 1. 三层权限

> 原文标题为「三层权限」，但表内实际列出 **L0 ~ L3 四层**，此处保留原文。

| 层级 | 角色 | 权限 |
| :--- | :--- | :--- |
| L0 | 框架维护者 | 定底层规则、阶位区间、结算公式骨架、惩罚原则；调汇率；批准晋升试炼；修改物品/能力基准值；设定家族风格标签 |

> 该结构与本节的 L0/L1/L2-L3 **实质对应，文字表述略有差异**（对话版把「副本作者与玩家」合并为底层）。本节保留脚本原文；对话版的完整论证见 [01-核心设计哲学.md](01-核心设计哲学.md) §5.3。

## 2. 审核者 checklist

审核者不需要理解副本玩法，只需按固定清单逐项检查：

1. 副本 ID 唯一，版本号合规。
2. 每个属性轴有合理的取值范围声明。
3. `can_modify_persistent_state` 为 false。
4. 结算模板 ID 存在。
5. 理论最高总评分 ≥ 基准分 × 该阶位最低比值。
6. 推导出的副本阶位与任务分值设计匹配（无畸高单任务）。
7. 公证物品/能力建议基准值在品质参考区间内。
8. 绑定类型与物品稀有度匹配。
9. 家族变体匹配家族风格标签。
10. 家族变体的魔改程度满足最低差异要求。
11. 副本不含对主神接口的直接调用代码（静态扫描）。

**全部通过 → 放行。任何一项不通过 → 退回并附原因。**

## 3. 分层意义

- **L1 按 checklist 审格式和边界**，不需要理解玩法，只做二元判断（允许/不允许）。
- **L0 管底层规则和汇率**，不需要管具体副本。
- 避免维护者成为众创规模的永久瓶颈。

如果只有 L0 一个维护者审所有副本，社区规模一上来，维护者就是永久瓶颈。**分层是众创项目能撑住规模的唯一路径。**

## 4. 家族风格标签

- 家族提交时，维护者给家族定一个**风格标签**（如「科技恐怖」「末日生存」「东方玄幻」「都市怪谈」）。
- 后续变体必须匹配这个标签。
- 审核者不需要逐字审查剧情衔接，只需检查「这个变体的设定是否匹配家族风格标签」。
- 这比逐字审查剧情轻松得多，也足够防止世界观崩坏。

## 5. 待定的治理参数

- **审核者人数门槛**：L1 至少几人放行一个副本？建议至少 2 人独立审核，防止单人误判或腐化。
- **L0 维护者人数**：初期可以 1 人，后期建议 3 人以上，避免单点瓶颈。
- **审核者选拔机制**：从活跃副本作者中选拔？还是公开招募？待定。
- **申诉通道**：副本作者对审核结果有异议时，向 L0 申诉。申诉处理时限待定。

## 6. 版权与内容合规

- 框架开源不等于可以随意分发受版权保护的角色、场景和剧情文本。
- 副本以「原创副本」或「公共领域/授权明确的世界观」为主。
- 同人性质的副本放在显式标记的社区内容池中，保留 takedown 通道。
- 贡献协议中明确：贡献者对其提交的 AI 辅助生成内容负责，项目方保留移除的权利。

## 7. 开源治理补充（来自已确认对话）

### 7.1 许可证组合建议

区分「核心」和「内容」，用不同的规则：

| 部分 | 建议许可 | 理由 |
| :--- | :--- | :--- |
| 框架核心（规则引擎、Schema、加载器） | MIT 或 Apache 2.0 | 降低贡献门槛 |
| 官方内容包 / 内置副本 | 更严格，如 CC BY-SA 或保留部分权利 | 防止有人直接把官方内容打包卖 |

参考：SandNet 用 AGPL-3.0 + 模块化架构，适合「防止被闭源 fork 后收割」；Project N.E.K.O. 用 Open Core + MIT（AI 逻辑、UGC 接口、基础交互永久 MIT，闭源部分只放在付费内容和增值服务上）。

### 7.2 贡献流程

**Schema validation CI → 人类 review → 合入。**

Godot 基金会要求 PR 必须经过维护者人工审批，即使是 MIT 项目也保留这条线。本项目需要类似机制：**自动校验 Schema 合规性，人类判断剧本质量与世界观一致性**。

### 7.3 AI 生成内容的两条纪律

- **禁止 AI 生成的代码进入核心仓库**（参考 Godot 2026 年 7 月政策）：高度依赖 AI 的贡献者未必能理解和修改自己提交的内容。核心引擎代码应由人类维护者把控。
- **Agent 辅助的剧本草稿停留在贡献者本地**：贡献者输入梗概 → Agent 按 Schema 产出初稿 → 人类修改 → 提 PR。产物不直接进入仓库，既利用效率，又避开「AI slop 涌入核心」。

### 7.4 合规风险

AI 生成内容在中国的游戏语境下，**著作权归属和训练数据供应链**是已进入司法和行业讨论的现实风险。需要在贡献协议中明确贡献者责任，并在 README 中说明：若 Agent 调用了第三方模型或资产服务，训练数据的合规性会沿供应链传导到最终游戏——**这一点要说在前面，而不是等有人主张权利时才处理**。
