## 0. 公证体系的设计来源

> 来源：turn 12（《轮回乐园》「乐园阵营」蓝本）。**这是本项目公证体系的概念出处**，可填补脚本中缺失的 1.1 节方向。

**核心思想：用「公证」取代「统一」。**

副本不需要和主神共享一套属性，但**它必须通过主神的「公证接口」才能被认可**。

### 0.1 两条硬规则

| 规则 | 内容 |
| :--- | :--- |
| **入场公证** | 副本加载时，主神只做三件事：① 校验副本声明的「属性轴」（如生存副本的健康/饥饿、战斗副本的力/敏/体/智）是否符合底层数据格式规范；② 确认副本引用的场景资产 ID 在库；③ **冻结轮回者进入时的状态快照** |
| **产物公证** | **未经主神公证的物品或能力，只能在当前副本内使用，无法带出** |

> **产物公证的意义**：直接堵死了副本作者通过私自定义超模道具来破坏跨副本平衡的可能——**东西可以用，但想变成「永久资产」，必须走主神的结算通道**。

### 0.2 公证的分级

> 高阶副本的产物需要经过更严格的公证。小说中区分「**完全公证**」与「**自由公证**」（后者属性部分保密但公证费更低）。
>
> ⚠️ **该分级的具体规则与费用数值在本项目中尚未定义**，仅作为分级方向的参考。详见 [04-副本阶位与家族.md](04-副本阶位与家族.md) §2。

### 0.3 公证是副本获得「合法身份」的唯一入口

> 「**公证-结算-惩罚**」三件套构成「自主性在副本，终裁权在主神」的最小闭环：
> 1. **公证接口**是副本获得「合法身份」的唯一入口；
> 2. **结算清单**是副本向主神「报税」的唯一通道，主神拥有汇率和评级的单方面定价权；
> 3. **沙盒权限**确保副本永远无法绕过接口直接篡改主神账本，越界即被拒绝或回滚。

> 完整架构说明见 [01-核心设计哲学.md](01-核心设计哲学.md) §4。

## 2. 绑定类型

三种绑定类型并存，在物品注册时**固定**，副本作者不能临时更改：

| 绑定类型 | 含义 | 适用场景 |
| :--- | :--- | :--- |
| `permanent` | 永久绑定，不可交易、不可丢弃 | 传说级、剧情关键物品 |
| `tradable` | 可交易（可卖给系统商店或 NPC） | 普通/稀有的通用装备 |
| `droppable` | 可丢失，死亡或严重失败时概率掉落 | 高风险副本产出的强力物品 |

**审核者检查**：绑定类型是否与物品稀有度和强度匹配。传说物品默认不可交易，除非有特殊理由。

**玩家体验**：拿到物品时就知道它的绑定类型，不存在「拿到手才发现不能交易」的意外。

> 绑定类型是否在注册时固定，对应 [09-待确认细节.md](09-待确认细节.md) 细节 4（倾向选项 A）。

### 2.1 ⚠️ 审计发现：绑定类型与惩罚扣除直接冲突

**严重度：高** ｜ **阻塞 D1**

| 出处 | 内容 |
| :--- | :--- |
| 本节 | `permanent` = 永久绑定，**不可交易、不可丢弃** |
| [设计决议记录.md](设计决议记录.md) D1 | 惩罚抵扣顺序 A(兑换点)→B(属性点)→**C(物品)** |

**矛盾**：惩罚要扣物品，但 `permanent` 物品被定义为**不可丢弃**。

**两种解法都会破坏一个已拍板设计**：

| 解法 | 后果 |
| :--- | :--- |
| `permanent` **不可**被扣除 | 这类物品**天然免疫惩罚** → 玩家会把资产转成 `permanent` 来躲避惩罚<br>**这正是 D1 废除旧押金公式的头号理由**（"惩罚深度被资产结构反向操控"），**以新形式复活** |
| `permanent` **可以**被扣除 | 本节的"不可丢弃"定义被推翻 |

**三个必须回答的问题**：

1. `permanent` 能否被惩罚扣除？
2. `droppable` 的"死亡或严重失败时**概率**掉落"与 D1 的"**确定**抵扣"是**两套机制**，**谁优先**？
3. 惩罚扣物品时，是玩家**自选**（可交出垃圾物品）还是主神**按价值抽取**？
   - 自选 → 惩罚可被轻易规避
   - 抽取 → 需要"物品价值排序"机制，**未定义**

> **反证这是遗漏而非有意留白**：本节的 `droppable` 已经写明"死亡或严重失败时**概率掉落**"——
> 说明设计时**想到了"惩罚会动物品"**，却对 `permanent` / `tradable` **完全沉默**。

**上位问题**：绑定类型事实上成了**惩罚系统唯一的物品可及性过滤器**，
但本章与 07 章**各自独立书写、从未对接**。补一句注释解决不了，需要一条明确决议。

### 2.2 ⚠️ 审计发现：`tradable` 的买方不存在

**严重度：低**

`tradable` 定义为"可卖给**系统商店或 NPC**"，但：

- 声望/排行榜类系统已由 D11 作废
- **"系统商店"与"NPC"在全库中无任何定义**（不在任何章节的机制表中）

> 需要一个买方存在，`tradable` 才有意义。

## 3. 产出规则

| 物品类型 | 兑换点可买 | 副本产出 |
| :--- | :--- | :--- |
| 普通物品（F/E 品质） | 是 | 是 |
| 稀有物品（D/C 品质） | 否 | 仅副本产出 |
| 史诗物品（B/A 品质） | 否 | 仅高階副本产出 |
| 传说物品（S 品质） | 否 | 仅顶级副本产出 |

**物品等级上限**由副本阶位决定。一个三阶副本只能产出物品等级 ≤ 对应上限的物品。

**品质上限**由副本阶位 + 结算评价共同决定。三阶副本的 S 评价才可能产出 A 品质物品；七阶副本的 B 评价就可能产出 A 品质。

## 4. 特殊事件标记

副本可产出标记，如「首次通关」「无伤通关」「在荒野副本中存活 30 分钟」。

### 4.1 标记的用途

- 解锁主神空间**特殊区域**（如「老兵酒馆」）。
- 解锁**特殊兑换通道**（如用标记兑换晋升试炼的入场资格）。
- ~~计入**本地声望记录**（排行榜）。~~ ⚠️ **已作废**，见 [设计决议记录.md](设计决议记录.md) D11（不做声望与排行榜）。

### 4.2 发现机制

**感知属性用「降低门槛」而非「提高概率」。**

隐藏事件有一个「感知阈值」。玩家感知属性达到阈值就自动发现，不需要 roll 概率。这更公平，也避免玩家反复读档刷概率。

感知属性因此成为一个「解锁隐藏内容」的硬门槛，价值明确。

> 对应 [09-待确认细节.md](09-待确认细节.md) 细节 6（倾向选项 A）。

### 4.3 单机下的声望替代

> ⚠️ **整节已作废。** 见 [设计决议记录.md](设计决议记录.md) **D11**：用户明确表示「暂时没有设计声望和排行榜的想法」。
> 以下原文仅作溯源保留。

单机模式下没有其他玩家，声望排行改为：

- **本地历史记录**：只记录玩家自己的历史最佳。
- **虚构 NPC 排行榜**：系统预设的 NPC 数据，玩家可以对比自己在「历史轮回者」中的位置。

后期接入 LLM 后，这些虚构 NPC 可以变成有对话能力的动态角色。
