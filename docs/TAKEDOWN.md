# 版权与移除契约（TAKEDOWN）

> 贡献契约四件套之一，小节标题登记于 `config/docs.json`。依据 01 §6、08 §6、08 §7 的已确认结论；未拍板流程参数只登记缺口，不在此发明流程或时限。

## 适用范围

- 框架开源**不等于**可以随意分发受版权保护的角色、场景和剧情文本（08 §6）。
- 副本应以原创或公共领域 / 授权明确的世界观为主；同人性质副本须显式标记为社区内容池内容。
- AI 辅助生成内容在适用范围内：贡献者对其提交负责，训练数据合规风险沿供应链传导（01 §6、08 §6）。
- 契约入口：[CONTRIBUTING.md](CONTRIBUTING.md) 的「AI 辅助生成内容责任」「训练数据供应链」「项目方保留移除权」三节。

## 移除请求的提出

权利人或有合理理由的贡献者可通过仓库 issue 提出移除请求，说明被质疑内容的位置与权利依据。贡献者在提交中披露的外部模型 / 资产服务及其授权状态，是判断授权是否明确的第一手材料。

本文不设未拍板的处理时限或申诉流程——这些参数在 08 §5 仍为待定，须拍板后才写入本契约。

## 处置方式

- 对授权状态不明或侵犯第三方权利的内容，保留 takedown 通道：由维护者按 CODEOWNERS 流程处理，并在 PR / issue 留痕。
- 对受保护路径的调整仍须 `@Radishe` 审核与 `gate-approved` 标签；移除动作不得绕过审核权，也不得由被审 agent 自行执行。
- 移除范围限于被质疑内容本身；不因此改变已拍板的评分与结算契约。
- 项目方行使移除权的事实与理由应可追溯，便于后续复核。

## 未拍板事项

以下仍为 UNRATIFIED，本文**不**给出具体规则或数值：

- 申诉通道与处理时限（08 §5）；L1 审核人数门槛、L0 维护者人数、审核者选拔机制（08 §5）。
- 场景规则标签的公证 / 税率**数值**（C15：`config/scenes.json` 的 `tax_or_notary_rate.value = UNRATIFIED`；逐标签交互规则 `per_tag_rules` 已 RATIFIED，但那不是数值）。
- 扭曲节点作为结算单元的边界（C16）与抹杀 / 非抹杀态的完整账本语义。

上述事项须由拍板后写入对应结构化配置与决议记录，不得由本契约或实现代填。

## 项目方保留移除权

对侵犯第三方权利、授权状态不明或违反贡献契约的内容，项目方保留移除的权利。该权利不因内容已合入、已打上 `gate-approved` 标签，或已作为示范副本登记而失效。
